# Compatibility

Souffleur depends on Claude Code's mod API, which is early access and changes between releases. This page lists the behaviour Souffleur relies on and the version each item was verified on. The evidence is in [background.md](background.md).

| `skill.prompt` does not fire for the re-attachment after compaction | 2.1.332 |
| `session.compact` runs a hook before and after; `/compact` reports trigger `manual` | 2.1.332 |

| `$.process.run` runs git without a shell and without repo hooks: `git ls-remote --tags --refs <url>` for the release look-up, `git -C <root> rev-parse --show-prefix`, `status --porcelain`, `describe --tags --exact-match HEAD`, `fetch -q --tags <repo URL>`, `rev-parse --verify refs/tags/<tag>`, `cat-file tag <object id>` and `checkout -q <object id>^{commit}` for the folder install. `$.process.hookEnv()` carries `CLAUDE_PLUGIN_DATA`, the folder the mod writes `allowed_signers` into with `$.fs.write`. The signature check was run by hand on git 2.53 in a scratch repository with two throwaway ed25519 keys: `git -c gpg.format=ssh -c gpg.ssh.allowedSignersFile=<file> verify-tag v9.9.9` with the line `souffleur namespaces="git" <public key>` exits 0 for a tag signed by that key (`Good "git" signature for souffleur`), exits 1 for the same tag with the other key's line (`No principal matched.`), and exits 1 for an unsigned annotated tag (`error: no signature found`). Two cases pass `verify-tag` although they must not install, so the mod checks them itself on the tag object: a PGP-signed tag verifies with `gpg.format=ssh` (git picks the verifier from the signature armor), and a ref `v9.9.7` pointing at the signed tag object of `v9.9.9` verifies (the signature does not cover the ref name). The mod requires the `-----BEGIN SSH SIGNATURE-----` armor and a `tag <name>` header equal to the tag name. It also requires a stderr line starting `Good "git" signature for souffleur with `, and it verifies the object id it resolved, not the tag name. The adapter tests mock `$.process.run`, so the git calls themselves are not run in a live session | 2.1.332 (git 2.53, by hand; mod API from the typings) |
